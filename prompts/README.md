# prompts — 可直接貼的六段

回：[README](../README.md)

每一份都是**整段複製就能用**的 prompt。
有些適合貼進規則檔當常駐規則，有些適合當下貼進對話。

| prompt | 什麼時候用 | 貼哪裡 |
|---|---|---|
| [01 對話開場：先報現況](01-session-start.md) | 每個新對話的第一句 | 對話裡（或做成 hook 自動送） |
| [02 實作前強制查詢](02-before-implementing.md) | 要新增任何功能／檔案／函式之前 | **規則檔常駐** |
| [03 要計畫，不要 code](03-plan-not-code.md) | 任何大於 30 分鐘的改動 | 對話裡 ＋ 記憶層 |
| [04 事故轉守衛](04-postmortem-to-guard.md) | 每次踩坑之後 | 對話裡 |
| [05 交付登記](05-delivery-registration.md) | 每次「做完了」之前 | **規則檔常駐** 或做成 skill |
| [06 規則檔瘦身](06-rules-file-diet.md) | 每月一次，或規則檔超過上限時 | 對話裡 |

---

## 投報率排序（只做得了一件的話）

```
1. 03 要計畫不要 code    ← 今天就能用，幾乎所有返工都來自跳過這一步
2. 04 事故轉守衛          ← 這一條產生複利：同一型錯誤只會花你一次
3. 02 實作前強制查詢      ← 專案越大越值錢
4. 05 交付登記            ← 三週後才會感謝自己
5. 01 對話開場            ← AI 會拿舊快照當現況，這條防的是那個
6. 06 規則檔瘦身          ← 等規則檔真的變肥了再說
```

---

## ⚠️ 兩件事

1. **不要一次全部貼進規則檔。** 規則正文的成本是「它的行數 × 每一次對話」。
   常駐的只留 02 和 05，其餘當下貼。
2. **改成你自己的話。** 這裡的措辭是為了對應**那個專案**踩過的坑；
   你的坑不一樣，措辭也該不一樣。
